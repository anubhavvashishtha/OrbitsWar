==============================================================
  OrbitsWar RL — Improvement Techniques
==============================================================
Kept only techniques with direct proof of improvement for
value-based / policy-gradient RL on strategy games.
==============================================================

--------------------------------------------------------------
 PHASE: VALUE FUNCTION (do before adding policy head)
--------------------------------------------------------------

[x] 1. REWARD SHAPING
    Proof: Ng et al. 1999 — dense rewards reduce sample complexity
           by orders of magnitude in sparse-reward environments.
    Problem: single win/loss at turn 500 is nearly useless gradient signal.
    Fix: add per-turn shaped reward in play_game_collect():
        r_t = 0.4*(my_ships_t - my_ships_{t-1})/total_ships
            + 0.4*(my_production_t - my_production_{t-1})/total_production
            + 0.2*(my_planet_count_t - my_planet_count_{t-1})/total_planets
    Terminal turn: r_T = won (overrides shaped reward)
    File: rl/self_play_trainer.py → play_game_collect()

[x] 2. OFFLINE TD ON REPLAY TRAJECTORIES
    Proof: offline RL (Levine et al. 2020) — replays contain full
           per-turn trajectories; treating each snapshot as an
           independent BCE sample throws away the temporal structure.
    Problem: 431 replays → 38K isolated snapshots with identical labels.
    Fix: parse consecutive turn pairs (feats_t, feats_{t+1}),
         compute shaped r_t between turns,
         apply TD target: V(s_t) ← r_t + γ·V(s_{t+1}),
         terminal: V(s_T) ← won.
    Result: 431 replays → ~43K correlated TD steps with dense signal.
    File: new function in rl/replay_trainer.py alongside existing BCE path.

[ ] 3. N-STEP TD RETURNS  (replace TD(0))
    Proof: TD(λ) unification (Sutton 1988) — TD(0) has high bias because
           it bootstraps after one step. N-step averages n actual rewards
           before bootstrapping, balancing bias/variance.
    Fix: G_t = r_t + γr_{t+1} + ... + γⁿ⁻¹r_{t+n-1} + γⁿV(s_{t+n})
    n=5 is a good start for 500-turn games.
    Only useful after reward shaping (#1) gives non-trivial r_t.
    File: rl/self_play_trainer.py → td_update()

[x] 4. SNAPSHOT EVERY TURN  (not every 5)
    Proof: direct consequence of #2 and #3 — n-step returns need
           consecutive transitions. Gaps of 5 break the chain.
    Fix: SNAPSHOT_EVERY = 1 in self_play_trainer.py.
    Do after #1 and #2 are in place.

--------------------------------------------------------------
 PHASE: POLICY (convert value-only to actor-critic)
--------------------------------------------------------------

[x] 5. ABSTRACT ACTION SPACE + ACTOR HEAD
    Proof: PPO (Schulman et al. 2017) — policy gradient with clipped
           surrogate objective is stable and sample-efficient.
           Abstract intents are standard for strategy games where the
           raw action space is combinatorial (SC2, Dota research).
    Fix: define 6 strategic intents, heuristic executes whichever PPO picks:
        0 = EXPAND        (best neutral planet)
        1 = ATTACK_WEAK   (weakest enemy planet)
        2 = ATTACK_LEADER (FFA: attack highest-production enemy)
        3 = DEFEND        (reinforce most threatened planet)
        4 = CONSOLIDATE   (pull ships to strongest owned planet)
        5 = SWARM         (multi-source coordinated attack)
    Add policy head to net.py: shared trunk → branch at 64:
        value  head: 64 → 1
        policy head: 64 → 6 (softmax)
    Replace TD loss with PPO clip loss + entropy bonus (β=0.01).
    GAE in buffer.py is already implemented — just needs the clip loss.

[x] 6. PROPER PPO CLIP LOSS
    Proof: PPO paper — clipping prevents large policy updates that
           destabilize training. You already saw this problem: TD(0)
           with LR=3e-4 oscillated 37% → 0% win rate.
    Fix:
        ratio  = exp(log_prob_new - log_prob_old)
        L_clip = min(ratio*A, clip(ratio, 1-ε, 1+ε)*A)   ε=0.2
        L_val  = (V(s) - return)²
        L_ent  = entropy of policy distribution
        L      = -L_clip + 0.5*L_val - 0.01*L_ent
    Requires #5 (policy head) to be done first.

--------------------------------------------------------------
 PHASE: GENERALIZATION (prevents opponent overfitting)
--------------------------------------------------------------

[ ] 7. OPPONENT POOL WITH SELF-PLAY SNAPSHOTS
    Proof: AlphaGo Zero (Silver et al. 2017) — training exclusively
           against a fixed set leads to cyclic strategies. Historical
           self snapshots prevent forgetting and increase diversity.
    Fix: every 5 rounds, export rl_value_fn.py + copy main.py as
         a new enemy in enemy agents/snapshot_rN.py.
         Load it into the pool for future rounds.
    Result: pool grows from 5 fixed → 5 + growing snapshot history.

[ ] 8. PRIORITIZED OPPONENT SAMPLING
    Proof: curriculum learning (Bengio et al. 2009) — sample opponents
           proportional to how often they beat you. Easy opponents
           give no gradient signal once mastered.
    Fix: track win_rate_vs[enemy_name] across rounds.
         sample weight = 1 / (win_rate_vs[enemy] + 0.1)
    Stops the agent overtraining against opponents it already crushes.
    File: rl/self_play_trainer.py → training loop

--------------------------------------------------------------
 PHASE: ARCHITECTURE (after policy is working)
--------------------------------------------------------------

[ ] 9. TURN ENCODING AS NETWORK INPUT
    Proof: positional encoding (Vaswani et al. 2017, game RL literature)
           — strategy games require different behavior in early/mid/late
           game. A static feature vector can't express timing.
    Fix: append [sin(turn/500), cos(turn/500)] to feature vector → 32 dims.
         Update OrbitsNet: Linear(32, 128).
         The sin/cos pair lets the network distinguish game phases
         without a hard-coded early/mid/late split.

[ ] 10. OFFLINE TD ON REPLAYS WITH DIVERSE OPPONENTS
    Proof: directly addresses strategy overfitting (discussed above).
           Your 431 replays contain games against dozens of different
           Kaggle agents — far more diverse than 5 fixed training enemies.
    This is #2 re-stated as a generalization fix, not just a data fix.
    Running offline TD on replays exposes the value function to strategies
    it will never see in self-play vs 5 fixed opponents.
    Implement together with #2.
